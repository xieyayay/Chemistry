    技术文档维护说明¶

    用 AI 写文档，不需要会 Markdown。

    一、打开方式¶

    安装 Claude Code¶

    在终端运行：

    npm install -g @anthropic-ai/claude-code

    启动¶

    在项目根目录 D:\UE5\Chemistry\aa\ 打开终端：

    claude

    进入对话后，把下面的提示词直接粘贴进去：

    我在维护一个 UE5 项目的技术文档，文档在 docs/ 文件夹下，是 MkDocs + Markdown 写的。
请先阅读 docs/ 下的文件，了解文档结构和风格，然后按我的要求编辑。

    二、常用操作¶

    改已有内容¶

    打开 docs/xxx/xxx.md，把 xxx 部分改成 xxx

    新增页面¶

    在 docs/xxx/ 下新建一个 xxx.md，内容是 xxx
然后在 mkdocs.yml 的 nav 里加上这个页面的入口

    全文改某个词¶

    把 docs/ 下所有 md 文件里的 xxx 都改成 xxx

    三、文档规范¶

    告诉 AI 这些规则，它会自动遵守：

    规则 说明
    中文为主 正文用中文，节点名用中文
    缩写对应的中文 细节（Details）、画布（Canvas Panel）、勾选框（Check Box）…
    代码块用 ```blueprint 蓝图节点和逻辑写进蓝图代码块
    每个页面有标题 + 一句话概述 # 标题 然后 > 一句话
    加截图用 ![](../images/xxx.png) 图放 docs/images/
    不要写理论 写"怎么做"，不写"是什么"

    四、案例流程¶

    案例 1：有人在任务系统里新增了一个变量，需要更新文档¶

    1. 对 AI 说： 

      打开 docs/systems/task-system.md，在数据表参数说明表格里加一行：
| NewVariable | 整数 | 这个变量的用途 |

    2. AI 改完 → 检查预览 → 提交

    案例 2：新增一个章节（比如多人联机）¶

    1. 对 AI 说： 

      新建 docs/systems/multiplayer.md，写多人联机系统的技术文档，
包括架构概述、用到的蓝图、同步方式。
然后在 mkdocs.yml 的 系统模块 下面加上这个页面。

    2. AI 写完后自己改内容

    五、怎么在本地查看效果¶

    装一次就行：

    pip install mkdocs-material

    然后：

    cd D:\UE5\Chemistry\aa
mkdocs serve

    浏览器打开 http://127.0.0.1:8000，文件改了自动刷新。

    六、风格参考¶

    写文档时直接给 AI 看现有的页面当参考：

    风格参考 docs/ui/widget-overview.md，帮我写 xxx

    现有的参考页面： - 控件讲解 → docs/ui/widget-overview.md - 系统架构 → docs/systems/task-system.md - 流程操作 → docs/animation/level-sequence.md - 速查手册 → docs/blueprints/blueprint-notes.md - 插件说明 → docs/plugins/third-party.md
